Interactive City Map — DreamHost Deployment Guide

Static site deployment with password protection and PMTiles support

Overview

This guide covers deploying the Interactive City Map as a static site on DreamHost shared hosting. The frontend is built with Vite + React and uses pmtiles for efficient map tile serving directly from static files (no tile server needed).

ComponentTechnologyDeployment
FrontendVite + React + MapLibre GLStatic HTML/JS/CSS
Map TilesPMTiles (static archives)Served via Apache with Range requests
AuthApache Basic Auth.htaccess + .htpasswd
RoutingSPA fallbackmod_rewrite → index.html
Note: This static deployment does not include the backend API (FastAPI + PostGIS). Features that depend on the backend (database queries, dynamic data) will not be available. If you need those, consider a VPS deployment with Docker.

Prerequisites

  • DreamHost shared hosting account with shell (SSH) access enabled
  • A subdomain configured in the DreamHost panel (e.g., map.resistor.technology)
  • SSH key-based authentication set up for your DreamHost account
  • Node.js installed locally (see .nvmrc for exact version)
  • PMTiles data files available locally

Step-by-Step Deployment

1 Configure DreamHost Subdomain

  1. Log in to the DreamHost Panel
  2. Go to Domains → Manage Domains
  3. Click Add Hosting to a Domain / Sub-Domain
  4. Enter your subdomain: map.resistor.technology
  5. Set the web directory to: /home/YOUR_USERNAME/map.resistor.technology
  6. Enable HTTPS (Let's Encrypt) under Secure Hosting
  7. Click Fully host this domain
DreamHost may take 15-30 minutes to provision the subdomain and SSL certificate.

2 Generate the Password File

SSH into your DreamHost server and create the .htpasswd file in your home directory (not the web root, for security): 

# SSH into DreamHost
ssh your-username@resistor.technology

# Create .htpasswd with your first user
htpasswd -c ~/.htpasswd yourusername
# Enter password when prompted

# Add additional users (omit -c flag after the first)
htpasswd ~/.htpasswd anotheruser
Security: The .htpasswd file must be placed outside the web root (in your home directory) so it cannot be downloaded by visitors. The .htaccess references it via absolute path.

3 Edit the Configuration

Before deploying, update two files with your actual DreamHost credentials:

3a. Update deploy/.htaccess

Change the AuthUserFile path to match your username:

# Change this line:
AuthUserFile /home/USERNAME/.htpasswd

# To your actual path:
AuthUserFile /home/your-actual-username/.htpasswd

3b. Update deploy/deploy.sh

Edit the configuration variables at the top of the script:

DREAMHOST_USER="your-actual-username"
DREAMHOST_HOST="resistor.technology"
DREAMHOST_PATH="/home/your-actual-username/map.resistor.technology"

4 Build and Deploy

Run the deployment script from the project root:

# Make the script executable (first time only)
chmod +x deploy/deploy.sh

# Full build + deploy
./deploy/deploy.sh

# Or build only (without uploading)
./deploy/deploy.sh --build-only

# Or upload an existing build
./deploy/deploy.sh --upload-only

The script will:

  1. Run npm ci and npm run build in the frontend directory
  2. Copy .htaccess into the build output
  3. Copy any .pmtiles files from data/ into dist/data/
  4. Upload everything to DreamHost via rsync
  5. Verify the deployment

5 Upload PMTiles Separately (if needed)

PMTiles files can be large. If you prefer not to include them in the rsync deploy, upload them directly: 

# Upload PMTiles to a data/ subdirectory on the server
ssh your-username@resistor.technology "mkdir -p ~/map.resistor.technology/data"

rsync -avz --progress \
  ./data/*.pmtiles \
  your-username@resistor.technology:~/map.resistor.technology/data/
PMTiles files are served directly by Apache. The browser's pmtiles library fetches byte ranges from the archive, so no tile server is needed. Apache's default configuration supports Range requests, and the .htaccess adds the necessary CORS headers.

Verify the Deployment

Browser Test

  1. Navigate to https://map.resistor.technology
  2. You should see a Basic Auth login prompt
  3. Enter your username and password
  4. The map should load with tile layers rendering

Command-Line Verification

# Test that auth is required (should return 401)
curl -s -o /dev/null -w "%{http_code}" https://map.resistor.technology
# Expected: 401

# Test with credentials (should return 200)
curl -s -o /dev/null -w "%{http_code}" -u user:pass https://map.resistor.technology
# Expected: 200

# Test PMTiles range request support (should return 206)
curl -s -o /dev/null -w "%{http_code}" -u user:pass \
  -H "Range: bytes=0-511" \
  https://map.resistor.technology/data/yourfile.pmtiles
# Expected: 206 (Partial Content)

File Structure on DreamHost

/home/your-username/
  .htpasswd ← password file (outside web root)
  map.resistor.technology/ ← web root
    .htaccess ← auth + rewrite + CORS rules
    index.html ← SPA entry point
    assets/ ← Vite-hashed JS, CSS, images
      index-[hash].js
      index-[hash].css
    data/ ← PMTiles archives
      chicago.pmtiles

Troubleshooting

ProblemSolution
500 Internal Server Error Check .htaccess syntax. Verify the AuthUserFile path is correct and the file exists. Check DreamHost error logs at ~/logs/map.resistor.technology/https/error.log
Map tiles not loading Verify PMTiles files exist in data/ on the server. Check browser DevTools Network tab for 403/404 on .pmtiles requests. Ensure Range request headers are not being stripped.
CORS errors in console Verify mod_headers is enabled on DreamHost (it is by default). Check that the .htaccess CORS rules for .pmtiles files are present.
SPA routes return 404 Verify mod_rewrite is enabled. Check that the RewriteEngine On directive is present in .htaccess.
No password prompt appears Verify .htpasswd exists at the path specified in AuthUserFile. Try using the full absolute path. Check that .htaccess overrides are allowed (DreamHost enables AllowOverride All by default).
PMTiles returns 200 instead of 206 Apache may not be honoring Range requests. This can happen if mod_deflate compresses the response (it strips Range support). The .htaccess only compresses text types, not application/octet-stream, so this should not occur. If it does, add: SetEnvIfNoCase Request_URI \.pmtiles$ no-gzip dont-vary

Manual Deploy (Without Script)

If you prefer not to use the deploy script:

# 1. Build the frontend
cd frontend
npm ci
npm run build

# 2. Copy .htaccess into the build
cp ../deploy/.htaccess dist/.htaccess

# 3. Copy PMTiles data (if applicable)
mkdir -p dist/data
cp ../data/*.pmtiles dist/data/

# 4. Upload to DreamHost
rsync -avz --delete \
  --exclude='.htpasswd' \
  dist/ \
  your-username@resistor.technology:~/map.resistor.technology/
