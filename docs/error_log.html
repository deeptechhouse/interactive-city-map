2026-10-02

Cook County owner names are cut off at 22 characters

Finding
Of 5,000 Chicago 2026 owner names, 568 are exactly 22 characters long, against about 200 at 21 or 23: e.g. MIGUEL ANGEL ORTEGA RA, ROBERT F DONOVAN DECLA. The last word of a 22-character name may be incomplete.
Why it matters
Sending a cut-off surname to Tracerfy's 1-credit name trace risks a paid wrong hit.
Handling
frontend/src/contacts/ownerNames.ts never uses a word at the 22-character cut point as the surname, and skips trusts, estates, initials and company names. Those owners go to the 2-credit address trace instead. Name misses are free and are automatically re-sent by address.

Tracerfy batch API: docs vs reality (all verified live)

JSON body refused
POST /v1/api/trace/ with application/json → HTTP 415. Fix: multipart/form-data with the rows as a csv_file upload (adapters/tracerfy_batch.py).
Name columns required
HTTP 400 "first_name_column is required…". Fix: send all six mapping fields, blank columns.
"normal" trace finds no owners
With blank names it matched nothing for 1001 W North Ave (instant found 10 phones). Docs: "Advanced discovers the owner from an address". Fix: trace_type=advanced — 2 credits/hit (normal is 1, instant 5).
Wrong status endpoint
GET /v1/api/queue/:id returns the queue's matched records (a list), not status. Fix: read pending/download_url from GET /v1/api/queues/.
Status throttled
HTTP 429 "Retry in intervals of 20 seconds". Fix: poll every 30 s; a 429 on status counts as "still pending".
Result column names
File says Email-1/Mobile-1/Landline-1; docs say email_1/mobile_1. Fix: column names normalised (case, "-" vs "_").
No DNC in batch results
Batch CSV has no dnc/tcpa/litigator columns. Results are stored dnc_checked=false; UI and CSV show "DNC not checked".

A test reached the real Tracerfy API

What happened
TracerfyBatchClient(api_key="") fell back to the real key in .env and sent a live request (refused with 415 — no queue, nothing charged; confirmed via GET /queues/).
Fix
Every backend test module now has an autouse fixture that blanks all paid-API keys from settings.

Provider failures were cached as "no match"

What happened
Tracerfy HTTP 402 (0 credits) was swallowed by the provider chain as a miss, cached, and shown as "No match" — and kept showing after credits were added.
Fix
Chains raise ProviderUnavailable when every provider errored; failures are never cached; the UI shows the real reason (out of credits / key rejected / not responding).

Dev server: “cannot be opened because the developer cannot be verified” (Rollup, fsevents, esbuild)

Symptom
npx vite crashed: @rollup/rollup-darwin-x64 … code signature … not valid for use in process; macOS dialog for fsevents.node.
Cause
frontend/node_modules was copied via Screen Sharing, so every file carried com.apple.quarantine, and the native binaries are unsigned — Gatekeeper refuses to load them.
Fix
xattr -dr com.apple.quarantine node_modules, then ad-hoc sign each native binary: find node_modules -name "*.node" -exec codesign --force --sign - {} \; plus the esbuild binaries. Re-run after any copy of node_modules from another Mac (a fresh npm ci avoids it).

Frontend tests: 51 interior tests fail with “document is not defined”

Symptom
Full vitest run: all src/interior/__tests__ component tests fail.
Cause
Two issues: vitest.config.ts sets environment: 'node', and the installed jsdom@29 cannot load on Node 20.11 (its dependency @exodus/bytes is ESM-only → ERR_REQUIRE_ESM; needs Node ≥ 20.19).
Workaround
New UI tests use // @vitest-environment happy-dom (added happy-dom@20.14.5, MIT). Interior tests are not fixed — options: add the same directive to them, or upgrade Node (.nvmrc) to ≥ 20.19 so jsdom works.
