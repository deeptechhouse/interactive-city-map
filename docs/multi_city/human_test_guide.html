1Start it

Pick one mode. Both use ports that avoid the Chicago copy (5173 / 8000).

Development mode (hot reload)

cd /Users/aaandy/_andy_ai_projects_2026/interactive-city-map-multicity
MAP_PORT=5180 PHONE_PORT=8010 ./start_map.sh

This opens http://localhost:5180. Switch city with the selector at the top left, or go straight to ?city=detroit or ?city=dayton.

Built mode (the way the Mac mini runs it)

cd /Users/aaandy/_andy_ai_projects_2026/interactive-city-map-multicity
PORT=8020 ./run.sh

The first run builds the map into frontend/dist-local/. That copy includes every city's data, about 280 MB.

Phone numbers (optional)

Business phone lookups need your Google and Foursquare keys. The worktree has no .env; to enable them, run cp ../interactive-city-map/.env . from the worktree. Without keys, everything else works and phones show "no listing found".

4Known gaps (not blockers for testing)

  • Sanborn, interior maps, railroad right-of-way, federal properties exist only for Chicago (later plan phases).
  • Discovery (business-type browser) is Chicago-only; it uses Chicago licence data.
  • POIs: Detroit has 304 and Dayton 344, because the shared OSM category map is narrow.
  • Dayton owner names on building tiles show only the first line ("… AND"); the contact panel shows the full name.
  • Dev mode with Postgres/Martin for Detroit/Dayton is not wired yet (city_registry / run.py). Static mode is the tested path.
  • Building tiles include owner names (public assessor records), the same as Chicago.
  • Blight covers tickets issued since 2021 (411K). The window is ADJUSTABLE in detroit.yaml.
